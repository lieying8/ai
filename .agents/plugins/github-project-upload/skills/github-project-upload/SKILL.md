# GitHub 项目归档与上传

## 确定位置和授权

先读取 GitHub 当前账号、目标仓库写入权限、分支及现有项目文件。默认仓库为 lieying8/codex，分支为 main，用户指定的位置优先。已有项目沿用原目录，先查目录与仓库首页，避免重复创建大小写不同或用途相同的目录。新项目沿用用户确定的名称，未指定时按仓库现有命名习惯选择。

从代码、README、Git 历史和本次修改确认项目名称、日期、现有版本与本次版本。日期采用用户时区。沿用已有版本体系，首次发布按实际情况确定，存在实质歧义时向用户确认。

用户要求准备或审核时，先完成可完成的整理，再交付审核单。用户已明确授权上传或审核通过后，继续提交和验证。仅整理时交付本地文件或 ZIP。已有授权继续有效。

## 项目文件与文档

核对入口、运行依赖、固定域名、绝对路径、外部服务配置和凭据。按用户已明确授权的凭据保存方式处理，避免在回复、日志或无关文件中重复输出凭据。影响实际部署的问题需修复，或逐项标明需要用户处理的配置。

实测可用的项目保留已有运行行为，改动围绕本次请求。主入口已有中文文件头时，更新真实日期、版本、简介和运行要求。PHP 的说明置于现有 <?php 后，HTML 用注释。记录已确认的访问地址或通用部署路径。

默认精简项目文件，按实际用途保留：
- README.md 集中写明名称、版本、日期、功能、使用步骤、环境要求、文本目录树及简短版本记录。
- 文本结构图放在 README 的 text 代码块中。列出运行所需、自动生成及用户需放入的文件；例如 files/ 下的 *.txt、*.md，标明来源。
- SVG 流程图保存为图片文件，并在 README 用相对路径直接显示。需要流程图时优先复用并更新已有图，按用户约定提供查看入口。
- 同一信息集中维护，默认合并重复的 TXT 结构图和短 CHANGELOG。复杂项目已有必要的独立文档时可保留，合并或删除前检查引用和实际用途。
- 当前目录保留当前可用代码，旧版本通过 Git 历史查找恢复。清理重复的版本文件前检查链接和运行引用。用户明确要求保留多个版本时照办。
- .gitignore 按实际需要设置。确需配置示例才增加示例文件，许可证按用户意愿添加。

文件名、域名和目录能自动适配时优先使用可迁移方案。对需要手动调整的域名、回调、绝对路径、环境变量、权限、数据库或 API 配置，在 README 和结构图对应位置说明“何时要改、改哪项、如何验证”。避免把假设的部署方式写成当前项目的必需步骤。

## 上传前审核

按下面的格式填写真实信息，按本次修改增减叶子条目。账号、位置先查询，可查询的信息由助手查明。README、版本记录和图等常规工作由助手完成。

✅ 表示条件已核实、该项已完成或可以在本次授权上传中完成。❌ 表示存在需要用户处理或确认的障碍，写清原因。测试项依据真实检查和用户反馈填写，注明有实质影响的未验证项，避免把未测试功能标成通过。最终核对单用于确认本次发布范围。

```text
上传到 GitHub 前审核
├── 账号：{账号}，仓库写入权限已核实 ✅/❌
├── 保存位置：{仓库} → {分支} → {项目目录} ✅/❌
├── 项目信息
│   ├── 名称：{项目名称} ✅/❌
│   ├── 状态：{已有项目，原目录已核对／新项目} ✅/❌
│   ├── 更新日期：{YYYY-MM-DD} ✅/❌
│   └── 版本：{当前版本 → 本次版本／首次发布版本} ✅/❌
├── 本次修改内容
│   ├── {新增、修改或删除的内容一} ✅/❌
│   ├── {新增、修改或删除的内容二} ✅/❌
│   ├── 更新 README 和版本记录 ✅/❌
│   └── 更新结构图和流程图，在 README 集中展示 ✅/❌
├── 部署与迁移：{域名、路径、依赖及配置要求已注明} ✅/❌
└── 测试结果：{实际检查的项目、结果及未验证项} ✅/❌
```

每项只保留实际对应的一个符号。纯文档项目等不适用的条目可省略。用户仅测试模板时给示例并标明示例，避免因此提交文件。

## 提交与验证

提交前核对入口文件、版本日期、README、图、相对链接、部署说明和本次实际修改一致。修改规则、模板或文件布局时，检查同目录配套指南及引用，并在同次提交中同步修订或合并，清理过时说明。新项目在根 README 项目列表加入中文用途与相对链接，已有项目检查简介是否需要随新增功能更新。

中文提交说明。优先将一次相关修改放在同一次提交，更新分支时核对远端当前提交。冲突时先读新状态再合并用户授权的变更，避免覆盖他人修改或强推。

提交后读取远端文件或校验内容哈希，核对入口与文档链接、预期的新增删除。打包交付时检查包内文件和部署目录。最终给出项目入口、README 内的结构图和流程图入口，以及必要的测试范围说明。
