## 平时怎么说

| 想做的事 | 可直接复制的话 |
| --- | --- |
| 先整理给我看 | 按咱们的 GitHub 模板整理，先发上传前审核单。 |
| 整理后直接上传 | 按咱们的 GitHub 模板整理并上传。 |
| 更新已有项目 | 更新原项目目录，沿用项目版本体系，补上本次变更。 |
| 只检查 | 检查这个项目的部署方式、迁移要求和存在的问题。 |
| 让其他 Agent 处理 | 先读取lieying8/ai 仓库里的 `.agents/plugins/github-project-upload/skills/github-project-upload/SKILL.md`，按要求整理，先发我审核。 |

带文件或项目目录发来即可。需要更换仓库、分支或版本时一并说明。审核通过后说「审核通过，上传吧」。

## 上传前怎么审核

助手先查询账号写入权限、分支和已有项目目录，完成可完成的准备，再用固定树状审核单报告。

- ✅ 表示条件已核实、已经完成或能够在本次授权上传中完成。
- ❌ 表示需要你处理或确认的实际障碍，后面写清原因。
- 测试结果按实际检查和你的反馈填写，列明有影响的未验证项。
- README、版本记录及项目图等常规整理工作由助手负责。

[审核模板与完整执行规则](SKILL.md#上传前审核) 集中维护在 Skill 中。

## 文件怎么整理

1. **项目位置**。已有项目先查原目录并沿用。新项目按已确定的名称或仓库现有习惯建目录。
2. **版本与文件头**。沿用实际版本体系，日期用用户时区的 `YYYY-MM-DD`。主入口中文注释按实际需要记录名称、日期、版本、用途、环境、地址及本次变更。
3. **README 集中展示**。放项目说明、日期、版本、使用步骤、环境要求、文本结构图、流程图展示和简短版本记录。
4. **结构图和流程图**。目录树写在 README 的 text 代码块里。需要 SVG 展示时保留图片文件，并在 README 用相对路径显示。目录树也标明运行时生成和部署者需放入的文件，例如 `files/` 下的 `*.txt`、`*.md`。
5. **精简文件**。重复的 TXT 结构图和短 CHANGELOG 合并到 README。复杂项目确有用途的独立文档继续保留。清理前检查程序依赖和文档引用。
6. **历史版本**。当前目录保留当前可用代码，通过 Git 历史查看和恢复旧版。按用户明确要求保留的多版本文件另行处理。
7. **部署与迁移**。检查固定域名、回调、绝对路径、运行依赖和配置。能自动适配的地方优先适配；需要手工改的地方写明何时改、改哪里、如何验证。
8. **首页和验证**。新增项目时更新仓库首页项目行，已有项目按功能变化更新简介。上传后核对远端内容、入口和相对链接，并说明测试范围。

配置示例、忽略规则及其他文件按项目实际用途增加。许可证按用户意愿添加。

## 仓库路径怎么写

- 仓库内使用相对路径，例如根 README 中的 `[在线文档浏览器](document-viewer/)`。
- 分享目录使用 `https://github.com/lieying8/codex/tree/main/document-viewer`，其中 `tree` 表示目录页，`main` 是分支。
- 分享单个文件使用 `blob/main`，查看某次提交使用 `commit/提交编号`。
