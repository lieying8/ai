## 提交前检查

1. **项目位置**。新项目放到与 `file-share/` 同级的英文小写目录，单词用连字符。更新已有项目时沿用原目录。
2. **中文代码文件头**。写明日期、名称、版本、简介、部署环境、项目地址或部署路径、GitHub 备份地址和本次更新。PHP 用注释，HTML 用 HTML 注释。版本未正式确认时首次用 `v0.1`，正式确认后用 `v1.0`。日期用 `YYYY-MM-DD`。
3. **项目 README**。开头标明项目名称、版本和日期。随后写用途、目录结构、部署环境、部署步骤、使用方法。配置、数据备份和回退按实际情况补充。
4. **结构图**。项目 README 和 `PROJECT_STRUCTURE.txt` 用同一份目录树。既画出仓库里的文件，也画出部署者要放进去或程序自动生成的文件，并在对应目录下标注来源。例如 `files/` 下写 `*.txt` 和 `*.md`。
5. **更新日志与配置**。用 `CHANGELOG.md` 记录该版本的实际变更。用 `.gitignore` 排除运行数据、系统文件和本地配置。有部署配置要求时附上示例。许可证由用户确认后添加。
6. **仓库首页**。新增或更新根目录 `README.md` 的项目行，使用相对链接。项目文档与仓库首页入口放在同一次提交。
7. **发布核对**。保留原始文件和需要回退的版本。提交后核对 GitHub 上的文件、版本、日期和首页入口，说明哪些已测试，哪些待实机验证。

## 仓库路径怎么写

- 仓库内写 `document-viewer/`。在根 README 可写 `[在线文档浏览器](document-viewer/)`。
- 分享目录用 `github.com/lieying8/codex/tree/main/document-viewer`。其中 `tree` 表示目录页，`main` 是分支。
- 分享单个文件用 `blob/main`，查看某次提交用 `commit/提交编号`。
