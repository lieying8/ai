# GitHub 项目归档与上传

1. 从请求和附件确定项目名称、版本、更新内容和操作。默认仓库为 `lieying8/codex`，分支为 `main`。新项目使用小写英文和连字符命名目录，与 `file-share/` 同级。已有项目沿用原目录。当前请求明确授权上传时才写入 GitHub。仅整理时交付 ZIP。「实测可用」「直接上传」表示保留运行逻辑，仍需完成中文文件头、项目内文档和仓库首页条目。只有用户明确要求仅归档原文件时才跳过模板。
2. 检查附件完整性、部署依赖和敏感信息。发现影响上传的问题时暂停上传并说明。保留原始文件包和已发布版本。首次未正式确认的归档用 `v0.1`，用户确认正式发布后用 `v1.0`。后续按用户确认的版本记录更新。
3. 为 PHP 项目的主程序补齐中文文件头。已有文件头就按实际信息更新。仅整理时保持程序行为。将下面的注释放在现有的 `<?php` 后，使用已确认的站点网址，未确认时填写部署访问路径。运行说明按需补充。

```php
/**
 * 日期：YYYY-MM-DD
 * 名称：项目中文名称
 * 版本：v0.1
 * 项目简介：一句话概括用途
 * 项目地址：站点网址或部署访问路径
 * 搭建环境：PHP 版本、所需扩展和服务器环境
 * 源码／备份地址：https://github.com/lieying8/codex/tree/main/项目目录名
 * 本次更新：实际新增、修改或修复的内容
 * 运行说明：按需注明配置、数据库或 JavaScript 依赖
 */
```

4. 补齐项目内的中文 `README.md`、`CHANGELOG.md` 和 `.gitignore`。README 写明功能、目录结构、运行要求和部署步骤。需要配置时才添加无密钥的示例。许可证由用户确认后添加。
5. 新项目获准上传时，在同一次提交中将项目文件放入目标目录，并在仓库根目录的 `README.md` 项目列表加入中文简介与相对链接。更新已有项目时核对首页条目，按需修正。提交说明用中文。遇到拒绝或远端冲突，先检查状态，禁止强推。
6. 提交前核对 PHP 主入口中文文件头、项目内 README.md、CHANGELOG.md、.gitignore 和仓库首页条目齐全，仓库根 README 不能代替项目 README。提交后核对远端文件与链接；仅打包时核对 ZIP 内容。回复 ZIP 或 GitHub 项目链接及提交链接，并简要区分已完成的检查和未实跑的功能。
7. 核对项目结构图。将用户部署后要放入的文件或程序自动生成的文件写在对应目录下，即使仓库中只有占位文件也要画出来。例如在 `files/` 下写明 `*.txt` 和 `*.md`，并标注由部署者放入。项目 README 与独立结构图应一致。
